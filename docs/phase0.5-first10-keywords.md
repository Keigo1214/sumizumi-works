## 4. 規則の読み方の分かれ道（データを見た後で気づいたもの）

規則の文言に、読み方が2つに分かれる箇所が2つあった。**どちらもデータを見た後で気づいたので、どの読みを採るかは実行者に決めてもらう**（`docs/phase0.5-provisional-genre.md` §7-1 の前例と同じ扱い）。

- **分かれ目1：R3 の「関係のある案件」に、POS などの機能として含むものを数えるか。** JSON の文言は「その商材そのもの」。「機能を含む POS も数える」は、A8.net の読み取りをサブエージェントに頼むときに Claude が足した解釈で、固定した JSON にはない。**この定義を書いたのは、検索候補の取得を始めたのと同じとき（検索候補の結果を見る前）**。ただし、1回目はログイン切れで何も読めず、**A8.net のデータを実際に読んだのは、検索候補の結果（R2 の通過・不通過）を見た後**（定義は変えずに再開した）。この順序は会話の記録によるもので、リポジトリのコミットからは確かめられない
- **分かれ目2：R3 の例外「R1・R2 を満たす候補が10未満のときだけ」**。字義どおりに読むと、R1・R2 を満たすのがちょうど10の今回は使えず、不足が大きくて入れても10に届かないときだけ使える（規則がさかさまに働く）。「**R1〜R3 を満たすものが10未満のとき**」と読むと、今回使える

## 5. 推奨：道 C（10本とも型A）

**理由**
1. **既に決まっていること（最初の10本は型A、設計書 §0）を変えない**。道 A・B で型B を混ぜると、この決定と設計を変えることになる
2. **選ぶものが、データを見る前に固定した16語の中だけで決まる**。道 A・B の R6 で埋めるときは、埋める候補をデータを見た後で選ぶことになる（2026-10-02 の v1 では型B 3本を推したが、別の組の判定を借りたもので、選び方に固定した規則がなかった。レビューの指摘4・5）
3. **10本の顔ぶれが分かれ目1の読みに左右されない**（変わるのは書く順の4番と5番だけ）
4. 分かれ目2の字義どおりの読みは、規則の目的（足りないときにハブ専用で埋める）と逆に働く

**弱いところ（隠さずに書く）**
- **専用の案件があるのは5本だけ**（POS・ネットショップ・ホームページ・予約・顧客）。在庫・シフトは POS などの機能としての案件だけで、店舗アプリ・自動釣銭機・オーダーエントリーは0件。この5本は、推薦のルール（設計書 §1-10）に従うと **A8.net にない製品を勧める記事になりうる**。提携審査用という役割への貢献は小さい（もしも・afb の目安の「記事5本以上」は、専用の案件がある5本で満たす）
- **案1 を満たす案件があるのは POS だけ**（Airレジ・ポスタス。機能も数えると顧客・在庫にも出るが、同じ製品）。ほかの記事の案件は、低い成果地点（無料登録など）を含む・確定率の表示がない・55%未満のどれかで、案1 を満たさない（確定率はプログラム全体の値なので、上位プランの成果地点だけに当てはめることはできない。案1 の数え方②〔2026-10-01 決定〕でも、5,000円未満の成果地点が1つでもあれば実測まで不合格）。Phase 0.5 は収益化を狙わない段階（STRATEGY Phase 0.5）なので、致命的ではない
- **案件のない記事（6〜10。少なくとも8〜10）が品質の関門を通るかは未検証**。関門は、一次資料・比較表・付加価値1つ（CLAUDE.md ルール1〜3。「ないなら出さない」）。自動釣銭機・オーダーエントリーの機器は料金を公開していないものが多い（推定。未検証）。出せない記事が出たときの扱いは §7 の4 で先に決めておく
- 在庫・顧客・シフトは、検索候補の多くが個人向け（「家庭用」「個人」）で、R2 はそれで通っている。上位に出るページは検索する人の多数の意図で決まるので、**題名に「お店の」と入れても、店舗の読者が来るとは限らない（推定）**。個人の流入は否認条件（レジを使わない業種、店舗情報を確認できない申込）に当たりやすい

## 6. 採らなかった道

- **道 A・B（字義どおり → R6 で埋める）**：型B を混ぜると、上の「既に決まっていること」を変えることになる。型B を早く書くことの利点（v1 では、テンプレートの検証と1本あたりの PV の実測を挙げた）は小さい（推定）。新しいドメインで型B 数本の PV は Phase 2 のしきい値の見直しに使えるほど確かな数にならず、STRATEGY §16 の「最初の型B記事10本で v1.0」は Phase 3〜5 の項目。また、ジャンルを変えると型B は最も流用しにくい。親の業種（飲食店）の型B を先に書くと、子の業種（居酒屋・カフェ）の型B が重複ルールで作れなくなり、もともと少ない在庫（§7-5：約15〜24組）をさらに減らす
  - それでも道 A・B を選ぶ場合は、埋める候補を選ぶ基準を**先に**書いてから、全部の候補（型B の各組、R2 で落ちたモバイルオーダーなど）に同じ列で当てはめる
- **R2 で落ちたモバイルオーダーを例外として入れる**：A8.net の案件は4件あり、「飲食店 モバイルオーダー 比較」「モバイルオーダー 料金 比較」という候補もある。しかし、結果を見た後で規則の例外を作ることになる。単独の型A にするかは、もともと「Phase 3 の手前で決める」としていた（§4）ので、そこで改めて判断する

## 7. 実行者に決めてもらうこと

1. **道 C（10本とも型A）でよいか**（推奨）。または道 A・B を選ぶか
2. **1本目の主キーワード**：規則（R4）どおりなら「**レジアプリ 比較**」。数え方は、R2 の候補の文字列の数で レジアプリ 5 ＞ POSレジ 3（子ども向けのおもちゃのアプリ「レジアプリ 無料 子供」を除いても 4 ＞ 3）。ただし不利な点がある：
   - 「無料」の言い換えを除いて**異なる語で数えると POSレジ 3 ＞ レジアプリ 2**（R4 の数え方にも読みの余地がある）
   - レジアプリの候補には「即売会」「同人 イベント」「子供」「現金のみ」もあり、店舗でない人の検索が混ざる（推定）。スマレジ・ポスタスは「レジを使わない業種」を否認し、Airレジは App Store からの申込を否認する
   - 「POSレジ 比較」の後ろの候補は10件（比較表・飲食店・小売など）、「レジアプリ 比較」は2件
   - USENレジの掲載ルールが勧める語は「POSレジ 比較」
   - Claude の推奨は「**POSレジ 比較**」（規則の字義からは外れる。題名と本文では「レジアプリ」も扱う）。規則どおりにする場合も、題名に両方の語を入れる
3. **補助金の扱いの線**：POSレジ・ホームページ作成・自動釣銭機の検索候補に「補助金」があり、かんたん注文（「補助金で最大75％OFF」）や HPDX（補助金プラン）が補助金を打ち出している。推奨は税と同じ線（**国の公的資料〔中小企業庁・事務局の公式ページ〕にある事実だけを書き、採択の見込みや「申請すべきか」は書かない。広告主の「最大◯％OFF」は書き写さない**）
4. **出せない記事が出たときの扱い**（結果を見る前の今、決めておく）。次のどれかに当たる記事は、品質の関門を外して出すことはしない：一次資料・比較表・付加価値1つがそろわない（CLAUDE.md ルール1〜3）、検索結果の上位を取ったら範囲の外の話（医療など）で占められていた。推奨の扱い：
   - その枠は、**R2 で落ちたグループのうち R3 の案件が多い順（モバイルオーダー 4 → セルフレジ 1 → 券売機 1）**の次の候補で埋める案を、実行者に諮る（R2 の例外になるので、承認を取る）
   - それでも作れなければ、**10本に満たないまま進める**（10本は目安。本数のために関門を外さない）

## 8. 基準の弱いところ（次に基準を決めるときのために）

1. **R2 は、消費者の検索が多い語を落とし、個人向けの検索で通る語を通す**。モバイルオーダー・セルフレジ・券売機は、店舗側の比較の候補（「飲食店 モバイルオーダー 比較」「セルフレジ 飲食店 おすすめ」「タッチパネル 券売機 比較」）があるのに、語だけの候補が消費者の話で埋まって落ちた。逆に、在庫管理アプリ（「家庭用 無料」）・顧客管理アプリ（「無料」「個人」）・シフト管理アプリ（「個人」。ただし「店長 無料」など店側の候補もある）は、個人向けの候補を含めて通っている
2. R2 の語の一覧は字義どおりに当てはめた。「券売機 値段」は「価格」と同じ意味だが、一覧にない語なので数えていない（数えると券売機は R2 を通り、案件1件で R3 も通る）
3. **A8.net のキーワード検索は取りこぼす**。Airレジ（題名は「POSレジアプリ」）は「POSレジ」では出ず「レジアプリ」でだけ出た。R3 の数は下限と見る
4. 自動釣銭機の保留1件（POS+ が「対応」と書くだけ）は0件として扱った。道 C では結果に影響しない
5. 次に基準を決めるときは、①R2 に「店舗側の語（飲食店・店舗・業務用など）を含む候補」を数える ②「関係のある案件」に機能として含むものを数えるかを書く ③例外の条件を「規則をすべて満たすものが足りないとき」と書く、を**データを見る前に**入れる
