### 注意（必ず読むこと）

- **テスト記事の中身は架空です。** 統計・料金・出典のURLはすべてダミーで、記事の冒頭にもそう書いてあります。照合の合格記録もテスト用に作ったもので、照合はしていません
- **公開するのは2時間以内**にします。手順Bで公開した時刻を控えてください
- **ASPの登録申請の前に行ってください。** 審査の担当者が架空の統計の記事を見ることを避けるためです
- サイトは noindex と robots.txt で検索エンジンから隠れていますが、**公開中はトップページの新着一覧・RSSフィード・サイドバーからは見えます**。訪問者はほぼいない時期なので、2時間以内なら影響は小さいと判断しています。公開直後に、これらの状態を私が確かめます
- 入っているプラグインに、SNSへの自動投稿やメールでの通知をするものはありません（Contact Form 7・CookieYes・SEO SIMPLE PACK・Site Kit・SiteGuard・UpdraftPlus・XML Sitemap Generator）
- **画面の文言は版によって違うことがあります。** 手順書の文言と同じ意味の項目があれば、それを使ってください。見当たらないときはそこで止め、スクリーンショットを送ってください
- WordPress 7.x では、編集画面の右側の設定パネルが「リストビュー」「設定（歯車）」「スタイル」のタブに分かれています。この手順書で「設定タブ」と書いたら歯車のタブです（版によってはタブがまとまっていることがあります。その場合も同じ意味の項目を使ってください）
- CTAのボタンは WordPress 標準の「ボタン」ブロックで確かめます。Cocoon 独自のボタン（「囲みボタン」など）は今回は確かめません

## 5. 私が行う確認（あなたの作業はなし）

公開されたページのHTMLを取得して、次を確かめます。

| 確かめること | §11 |
|---|---|
| ページに noindex の指定があるか。RSSフィード（`/feed/`）とトップページに出ているか | 安全 |
| 本文の表が表として出ているか。HTMLのコメントが本文に見えていないか | 1 |
| カスタムHTMLブロックの中身が、そのまま（自動整形されずに）出ているか | 1 |
| Cocoon の「横スクロール」の表の囲み（`scrollable-table`）が付いているか | 2 |
| CTA が表示され、外側に `cta` クラス、ボタンに `rel="sponsored nofollow"`、計測用の画像があるか | 2・9 |
| アイキャッチ・シェアボタン・投稿日などと、広告表示の順序 | 3 |
| 投稿日と更新日の表示。**更新日時を時刻まで記録する**（ページの `<time datetime>` と構造化データの `dateModified`）。手順Dの判定の基準になる | 6 |
| 参考資料・更新履歴が表示されているか | — |
| **取得したページが新しいか**（応答ヘッダーのキャッシュの有無と、更新日時で確かめる）。古ければ、サーバーキャッシュの削除をお願いする | 安全 |

> 私の作業メモ：`postcheck.py` はテスト用の設定（`tools/dev/build_wptest.py` が作る `build/wptest-work/config.yaml`）を `-c` で指定して実行する。本番の `data/asp-programs.csv` にはテスト用の案件がないため。（2026-09-30 の実施時は、前のセッションの一時フォルダにあった同じ内容の設定を使った）

**公開後の照合ツール（`postcheck.py`）の期待結果**：このページでは**指摘0件**になるはずです。

| 出てはいけない指摘 | 意味 |
|---|---|
| 数値の書き換え・不足・余分（number_changed / missing / extra） | 本文の数値が正本と食い違う。出たら、Cocoon が本文の中に何かを差し込んでいる可能性があり、照合の除外の設定を見直す |
| マーカー・`{{` の残り | 反映ファイルの不具合 |
| 広告表示の欠落・位置 | 広告表示が本文の先頭にない |
| rel のないアフィリエイトリンク、CTA の中の数値・余分な要素、計測用の画像の欠落 | CTA の同期パターンの作り方の問題 |

> **照合ツールの限界**：`postcheck.py` は本文（`.entry-content`）の中だけを見ます。本文より上にあるアイキャッチやシェアボタンの位置は判定できないので、§11 の3は手順Cのスマホの画面で判断します。
> サイトは robots.txt で全体を止めているため、`postcheck.py` は既定ではページを取得しません。自サイトなので `--ignore-robots` を付けて直接取得するか、私が取得したHTMLを `--html-file` で渡して照合します（2026-09-30 の実施では後者を使った）。

## 10. 結果の記録（2026-09-30 実施）

**実施の方法**：実行者の依頼で、Claude がブラウザ（Claude in Chrome／アプリ内ブラウザ）と、ログイン中の管理画面の REST API を使って実施した。**公開・Cocoon設定の保存・記事の保存のボタンは、Claude 側の安全の仕組みで止められたため、実行者が押した**（設計書の「公開は実行者だけ」とも一致）。環境：WordPress 7.1.2、Cocoon 2.9.3.1。

| §11 | 結果 | ツール・設計書への反映 |
|---|---|---|
| 1（案1a：HTMLを貼る） | ブロックエディタは「カスタムHTML」2つとCTAのパターン1つを、すべて**有効なブロック**と判定。開いただけでは本文は変わらない。保存を2回しても有効なまま | 問題なし |
| 1（案1b：Markdownを貼る） | 表・見出し・リストは正しくブロックに変換される。ただし**参考資料のURLが自動でリンクになる**（参考資料を既定でリンクにしない方針と食い違う）。CTAは別に入れる必要がある | 採用しない方向 |
